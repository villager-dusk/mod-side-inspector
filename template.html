我们如何判断运行端

工具结合描述文件、公开发布资料、JAR 文件哈希和静态代码信号，不执行 Java 代码。v2.0 增加 Modrinth / CurseForge 核验，判断来源会明确标注。

Fabric
读取 fabric.mod.json 中的 environment。client 为客户端，server 为专用服务端，* 或省略为双端可加载。
Quilt
读取 quilt.mod.json 中的 minecraft.environment。client 为客户端，dedicated_server 为专用服务端，* 或省略为双端可加载。
Forge / NeoForge
读取 TOML 描述文件。Forge 的顶层 clientSideOnly = true 为客户端专用；其他情况继续查找文件指纹、平台资料和入口类注解，再进行静态代码分析。displayTest 及依赖的 side 不作为运行端结论。旧版 mcmod.info 仅用于识别信息。
检测边界
只分类所选目录中的外层 JAR；不递归展开 JAR 内的嵌套依赖，不验证游戏启动、模组依赖、联机兼容性或作者声明是否准确。文件匹配表示 JAR 对应已发布文件；平台运行端标签仍是项目级资料。代码推断不等于已核实，注册器或类引用只能提供线索，不能据此自动删除文件。多加载器声明不一致时标为待确认。损坏、加密或超出读取限制的文件会单独列出。

联网时仅发送文件哈希或指纹，CurseForge 实时 API 需要你提供 Key；Key 不会存储。
规则参考：Fabric 文档 ↗ Quilt 规范 ↗ Forge 文档 ↗ NeoForge 文档 ↗

发布平台联网核验

Modrinth 仅接收 JAR 的 SHA-1；CurseForge 仅接收文件指纹。均不上传 JAR、目录路径或文件名。

CurseForge 官方接口需要 API Key。不填时只联网核验 Modrinth；已内置的 CurseForge 项目资料仍会在本地使用。

Key 经当前工具转发给 CurseForge 官方接口，不写入存储。没有有效 Key 时无法验证官方实时指纹匹配。

未匹配到的文件不会被强行归类；修改版、自制模组、未收录文件仍可能需要代码推断。
